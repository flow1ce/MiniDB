\# SQL 编译器模块贡献-范雪雯



\## 负责模块



负责项目中的 SQL 编译器部分，主要涉及 `sql\_compiler` 目录下的词法分析、语法分析、抽象语法树、语义检查、执行计划生成和查询优化模块。



\## 完成内容



\- 实现词法分析器，将 SQL 文本转换为带有行号和列号信息的 Token，支持关键字、标识符、数字、字符串、注释和常用运算符的识别。

\- 实现递归下降语法分析器，支持 `CREATE`、`INSERT`、`SELECT`、`UPDATE`、`DELETE`、索引、事务、权限等语句，以及 `JOIN`、`WHERE`、`GROUP BY`、`ORDER BY`、`LIMIT` 和 `OFFSET` 等子句。

\- 设计并完善 AST 数据结构，用于统一表示 SQL 语句和表达式，并支持转换为字典和 JSON 结构，便于调试及前后端展示。

\- 完成语义检查，包括表和列存在性、表达式类型、插入列和值数量、数据类型匹配、聚合函数使用以及多表查询中的列名歧义检查。

\- 将 AST 转换为逻辑执行计划，构建扫描、过滤、投影、连接、分组、排序和分页等计划节点。

\- 实现查询优化，包括常量折叠、布尔表达式化简、扫描列裁剪，以及满足条件时选择索引扫描，降低查询执行开销。

\- 统一词法、语法和语义错误的分类与定位，使错误信息包含阶段、原因和 SQL 行列位置。



\## 测试与验证



通过词法位置和非法字符测试、AST 与执行计划测试、语义错误测试、计划 JSON 序列化测试，以及带索引的 `SELECT`、`UPDATE` 和 `DELETE` 查询测试，验证了 SQL 编译流水线的正确性和模块之间的协作关系。



\## 个人收获



通过本模块的实践，理解了 SQL 从源文本经过词法分析、语法分析和语义检查，最终生成并优化执行计划的完整过程，掌握了递归下降分析、AST 建模、类型检查和查询优化等方法，也加深了对数据库系统模块化设计和编译器工作原理的认识。
